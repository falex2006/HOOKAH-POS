# Карта сайта HOOKAH POS

> Историческая карта, заменённая в UI-01.1 от 2026-10-09. Действующие источники: [SITE_TREE.md](SITE_TREE.md), [site-map.json](site-map.json) и [матрица маршрутов и ролей](docs/design/UNIFIED_UI_2026-10-09/ROUTE_ROLE_MATRIX.md). Этот документ сохранён для истории; новые экраны и изменения прав регистрируются в действующей карте. Описанные ниже роли и маршруты не являются актуальной приёмкой.

## Точки входа

```text
/login                         Авторизация и первичная настройка владельца
├─ /                           Главная рабочая панель (зал и заказы)
│  └─ /                        Рабочая панель зала и заказов по правам вошедшего пользователя
└─ /admin                      Панель управления
   ├─ /admin#staff             Персонал и доступы
   ├─ /admin#staff-schedule    График сотрудников (view) / Мой график (self-only)
   ├─ /admin#staff-attendance  Выходы сотрудников (policy / approval / close)
   ├─ /admin#tasks             Задачи
   ├─ /admin#settings          Центр настроек
   ├─ /admin#company           Данные заведения
   ├─ /admin#venue-layout-settings  Залы и рабочая зона
   ├─ /admin#lock-security     PIN и автоблокировка
   ├─ /admin#settings-dashboard-modules  Настройка главной
   ├─ /admin#shift-control      Смена и касса
   ├─ /admin#loyalty            Система лояльности
   ├─ /admin#audit             Журнал изменений
   └─ /admin#diagnostics       Диагностика (developer)
```

`/` — главный операционный адрес. `/admin` — отдельный административный режим. Hash-пункты являются подразделами одной панели и не создают новые HTML-страницы. Исключение по назначению, не новый URL: «Мой график» доступен из рабочего меню по `staff_schedule_self` и открывает только personal read-only renderer на `/admin#staff-schedule`; это не доступ к административному dashboard. При `staff_schedule_view` тот же адрес открывает управленческий график. «Выход на работу» для сотрудника остаётся в рабочем контуре `/` и открывается отдельным доступным диалогом, без перехода в admin. Управленческий маршрут `/admin#staff-attendance` требует одно из `staff_attendance_policy_manage`, `staff_attendance_approval`, `staff_attendance_close`; по умолчанию показывает обзор, вкладка правил/доступа видна только при соответствующих правах. Уведомления ведут на `/#staff-attendance` или `/admin#staff-attendance`; личный bell показывает только attendance-уведомления, без финансовых категорий. Отметки посещения не создают кассовую смену и не записывают автоматически зарплатные `staff_work_logs`. Self-only календарь не показывает справку/планирование/редактирование; управленческая справка графика содержит15 поисковых тем. Детали темы и навигации: [SITE_TREE.md](SITE_TREE.md); минимальные DTO: [API.md](API.md).

## Границы ролей

| Узел | Владелец / администратор | Управляющий | Персонал |
|---|---:|---:|---:|
| Рабочая панель, заказы, гости | да | да | по разрешениям |
| Бронирования и доставка | да | да | по разрешениям |
| Склад и финансы | да | по разрешениям | по разрешениям |
| Персонал и роли | да | нет | нет |
| Данные заведения и сеть | да | нет | нет |
| Настройки интерфейса и безопасности | да | рабочие настройки | нет |
| Диагностика | developer | нет | нет |

Навигация скрывает недоступные узлы, а API всегда повторно проверяет разрешения.

## Правила URL и размещения

1. Один экран — один канонический URL из `SITE_TREE.md` и `site-map.json`.
2. `/` и `/admin` не переименовываются и не получают альтернативных главных адресов.
3. Прямые `*.html` — внутренние шаблоны и делают `308` на канонический URL.
4. Завершающий слеш у вложенных маршрутов делает `308` на slashless-вариант; `/` не перенаправляется.
5. API находится только под `/api/*`.
6. Hash применяется только для подразделов `/admin` (`staff`, `tasks`, `loyalty`, `shift-control`, `settings` и их панели); большие разделы получают отдельный маршрут.
7. `/inventory` использует query-параметр `view` для семи сохраняемых представлений одной складской области. Это состояние поддерживает обновление, закладки и историю браузера; `?view=stock` равен адресу `/inventory`.
8. Для Sites каждый канонический маршрут имеет `dist/<route>/index.html`, синхронизированный с корневым шаблоном.
9. Ссылки меню не указывают на `*.html`.
10. При добавлении пункта обновляются карта, `SITE_TREE.md` и контракт маршрутов.

## Связи разделов

```text
Рабочая панель → Заказы → Оплата → Финансы
Рабочая панель → Бронирования → Гости
Склад → Цех / подцех / категория → Позиция → Техкарта
Техкарта → Продажа → Списание → Себестоимость → Финансы
Персонал → График → Выход на работу (отдельный факт) → Зарплата → Расходы → Финансы
Настройки → Залы → Столы / зоны / VIP-комнаты → Рабочая панель
```

## Порядок бокового меню администратора

Меню следует ежедневной модели работы заведения. После главной панели первым идёт зал, где начинается и ведётся обслуживание; журнал заказов и бронирования идут до справочников. «Меню» содержит продаваемые позиции и составы, «Склад» — закупки, остатки и структуру хранения. Финансы, кадровые и системные действия находятся ниже и раскрываются по запросу. Внутри страницы не дублируются пункты, уже доступные в боковой навигации.

```text
Главное
└─ Главная                         /admin

Операции
├─ Зал                             /
├─ Журнал заказов                  /orders
├─ Бронирования                    /reservations
├─ Гости                           /clients
└─ Доставка                        /delivery

Меню (раскрываемая группа)
├─ Каталог товаров                 /inventory?view=products
└─ Технологические карты           /inventory?view=recipes

Склад (раскрываемая группа)
├─ Остатки                         /inventory?view=stock
├─ Пополнение запасов              /inventory?view=auto-orders
├─ Поставки и списания             /inventory?view=movements
├─ Заготовки и премиксы            /inventory?view=premixes
└─ Цеха и категории                /inventory?view=directories

Финансы (одиночный пункт)         /finance

Команда
├─ Персонал                        /admin#staff
├─ График сотрудников              /admin#staff-schedule
├─ Выходы сотрудников              /admin#staff-attendance (policy / approval / close права)
├─ Роли и права доступа            /admin#permissions
└─ Задачи                          /admin#tasks

Система
├─ Система лояльности              /admin#loyalty
├─ Настройки                       /admin#settings
└─ Telegram                        /integrations
```

У каждого пункта свой значок с тем же смыслом: зал — схема столов, журнал — чек, бронирование — календарь, гости — группа людей, склад — коробка, финансы — график, персонал — карточка сотрудника, задачи — список отметок, лояльность — подарок, настройки — шестерёнка, Telegram — бумажный самолёт. Не использовать один значок для разных действий, если есть подходящий отдельный символ.

В рабочем меню `/` отдельная кнопка «Выход на работу» доступна только при серверном `staff_attendance_self`; она открывает личную панель и не ведёт на управленческий маршрут. Маршрут `/admin#staff-attendance` и пункт «Команда → Выходы сотрудников» видны при любом из `staff_attendance_policy_manage`, `staff_attendance_approval`, `staff_attendance_close`. Обзор открыт первым; вкладка «Правила и доступ» показывается только соответствующим пользователям. Владелец отдельно выдаёт права на настройки, согласование и завершение чужой отметки. План графика, кассовая смена и факт личной attendance-сессии остаются разными процессами; личные уведомления не раскрывают финансовые категории.
