# FIX-04.3 — диалог истории возвратов

Дата: 08.10.2026. Локальная синтетическая среда; production и GitHub не затрагивались.

## Изменение

Исправлен D09: секция «Исходные оплаты» повторно добавлялась в диалог, когда у сотрудника не было формы возврата (в том числе при просмотре закрытого заказа с правом `finance_read` и у владельца на открытом заказе). Теперь секция выводится ровно один раз в каждой из двух взаимоисключающих ветвей: внутри формы для разрешённого возврата либо отдельно для read-only состояния.

Добавлены scoped-стили `.order-refund-dialog` для тёмного оформления, backdrop, размеров/прокрутки и строк оплат/истории. На узкой ширине строка перестраивается; общий каркас CRM и другие диалоги не затрагиваются.

Права, API, финансовые расчёты и обработка возврата не менялись. Сохранены `pendingIntent`, исходный payload и `idempotencyKey` для безопасного повтора после неопределённого сетевого ответа.
