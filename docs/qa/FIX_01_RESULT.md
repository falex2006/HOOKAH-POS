# FIX-01 — единый серверный расчёт прав

**Статус: выполнен локально, 08.10.2026.** Область: ROLE-01/02/05, backend login/session/profile. Приёмка интерфейса ROLE-03/04 — отдельный FIX-02; готовность всего рабочего пакета не заявляется.

## Что изменилось

- Новый чистый resolver `effective-permissions.js` возвращает права и объяснение `permissionPolicy`: источник, наличие системного потолка, исключённые им capabilities.
- `server.js` использует один resolver для авторизации, login, session и profile. `user.workspacePermissions` совпадает с верхнеуровневыми permissions. Trusted PIN возвращает свежие права из запроса, memory-сессия обновляет роль/персональные scopes из staff.
- `db.js` читает custom/system источники одним JOIN в контексте активного venue. Наличие источника определяется отдельным boolean, поэтому пустой список не путается с отсутствующей настройкой. Custom JOIN ограничен organization/venue/active.
- Ошибка загрузки источников закрывает доступ: нет поглощённого сбоя system lookup с возвратом к базе. Profile при невозможности достоверного чтения возвращает503, а не ложный базовый набор. Для устаревшей схемы теперь необходимы актуальные миграции; новой миграции в FIX-01 нет.
- Dockerfile включает новый серверный модуль. Docker-образ не собирался и не публиковался.

## Принятый контракт

1. Owner/platform_owner сохраняют защищённый базовый набор. Нетронутые роли сохраняют точные прежние defaults, включая read-only manager.
2. Персональные `[]`/null означают наследование; персональный null при записи нормализуется в[] и остаётся owner-only.
3. Активная custom role выбирается вместо персональных scopes; её[] запрещает направления.
4. Явная системная настройка задаёт верхнюю границу. Пересечение вычисляется по развёрнутым permissions, а не по названиям групп. System[] запрещает бизнес-доступ. System/custom null на записи отклоняется400.
5. `bar_tasks`/`hookah_tasks` остаются только при разрешённых orders. `diagnostics` у исходного обладателя остаётся только с settings, чтобы не обходить запрет через связанные API.

Это может сузить доступ при ранее конфликтовавших system+custom/personal настройках. Карточка/API теперь показывают итог и источник ограничения; визуальное объяснение и устранение клиентского объединения с базой входит в FIX-02. Полный контракт: `docs/architecture/EFFECTIVE_PERMISSIONS_CONTRACT.md`.
