# FIX-03.2 — актуальность каталога

Дата: 08.10.2026
Среда: локальная синтетическая QA-среда; production и GitHub не затрагивались.

## Изменения

- Рабочее место перечитывает каталог при каждом открытии меню, при возврате к открытому меню и каждые 60 секунд, только пока меню открыто и вкладка видима.
- Одновременные триггеры используют один запрос. Ответ применяется только для прежних поколений доступа и запроса, если точка совпадает и меню остаётся открытым.
- Запрос использует `cache: 'no-store'` и передаёт `expectedVenueId`. Сервер выставляет `Cache-Control: no-store` и отвечает `409 venue_context_changed`, если активная точка не совпала.
- Ошибка обновления блокирует продажу по прежнему списку и предлагает повтор. После серверного `product_not_found` каталог перечитывается; уведомление различает успешное и неудачное обновление.
- Поиск и уже открытый заказ сохраняются. Новая строка заказа использует возвращённые сервером имя и цену; существующие строки и историческая цена не меняются.
- Синхронизация опубликованных локальных assets выполнена штатным скриптом; `app.js` — ревизия 206.

- `scripts/staff-catalog-add-pending-qa.mjs` — PASS: серверная цена, повторные нажатия, ошибки добавления и обновление каталога после `product_not_found`.

- Двухсессионная Edge-проверка завершена: бармен открыл каталог и увидел 200 ₽; отдельная авторизованная сессия владельца изменила цену на 225 ₽. Уже открытый каталог сотрудника сохранял загруженное значение до повторного открытия. После закрытия и повторного открытия меню бармен увидел 225 ₽.
- После проверки цена возвращена на 200 ₽, временная QA-учётная запись сотрудника отключена, активные сессии завершены. Заказ не создавался, оплата и складские движения не выполнялись.
- Попытка изменить другую позицию, связанную с открытым заказом, была корректно отклонена сервером; для сценария использована отдельная неиспользуемая QA-позиция.

Реализация, клиентские проверки и двухсессионная Edge-приёмка для бармена завершены локально. Бармен после повторного открытия каталога увидел новую цену владельца. Исторические строки заказа не изменялись. Production и GitHub не затрагивались.
