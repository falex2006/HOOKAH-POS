# FIX-03.2 — актуальность каталога сотрудника

## Исходный факт

`docs/qa/AUDIT_2026_10_08_BROWSER_FINAL.md` подтверждает D02 в двух независимых локальных сессиях: сотрудник видел цену 200 ₽ после изменения владельцем на 275 ₽, а созданная строка заказа получила актуальные 275 ₽. Уже добавленная строка сохранила исторические 200 ₽. Причина в рабочем месте: каталог загружался при проверке сессии, но повторное открытие каталога не запрашивало свежие данные. `GET /api/products` и создание строки заказа читают текущие данные сервера.

## Контракт проверки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Каталог открыт после изменения владельцем цены | Обновлённая цена появляется в каталоге; новую строку сервер сохраняет по своей текущей цене |
| Владелец архивировал позицию | Позиция пропадает после обновления; сервер отклоняет попытку добавить архивную позицию |
| Владелец добавил позицию | Она появляется после обновления без перезагрузки страницы |
| Уже открытый заказ и ранее добавленная строка | Заказ остаётся выбранным; имя/количество/цена старой строки не меняются |
| Каталог закрыт или вкладка скрыта | Нет фоновых запросов каталога; периодическое обновление ограничено видимым открытым каталогом |
| Каталог снова открыт / вкладка вернулась | Выполняется актуальное чтение; параллельные триггеры не создают лишних запросов |
| Ошибка сети при обновлении | Старые цены не выдаются за подтверждённые свежие; состояние закрыто для добавления и доступен явный повтор |
| Сессия/точка изменились во время чтения | Поздний ответ старой сессии, точки или запроса не перезаписывает актуальный каталог |
| Бармен и кальянщик | Один и тот же контракт обновления, разрешения сохраняются |

## Набор проверок

- `scripts/staff-catalog-load-state-contract.mjs` — состояния загрузки, пустого каталога, ошибки/повтора, защита от устаревшего доступа и безопасное отображение.
- `scripts/staff-catalog-refresh-runtime-qa.mjs` — повторное открытие, периодическое обновление только видимого открытого каталога, single-flight, no-store, гонки точки/доступа/порядка ответов, fail-closed и повтор.
- `scripts/staff-catalog-add-pending-qa.mjs` — добавление использует цену, возвращённую сервером; повторные нажатия не создают лишние строки.
- Edge с двумя независимыми локальными сессиями: сотрудник открыл каталог с ценой 200 ₽; владелец изменил её на 225 ₽. После закрытия и повторного открытия каталога сотрудник увидел 225 ₽. Тестовая цена восстановлена до 200 ₽, временный сотрудник отключён.

Baseline был read-only; ниже фиксируются проверки после реализации. Двухсессионная Edge-приёмка актуальности цены завершена.

## Локальные проверки

| Проверка | Результат |
| --- | --- |
| `node --check` для трех catalog QA-скриптов | PASS |
| `staff-catalog-load-state-contract.mjs` | PASS |
| `staff-catalog-refresh-runtime-qa.mjs` | PASS: reopening, видимый 60-секундный опрос, single-flight, no-store, гонки точки/доступа/ответов, закрытое состояние и повтор |
| `staff-catalog-add-pending-qa.mjs` | PASS: добавление использует цену сервера; `product_not_found` обновляет каталог |
| `git diff --check` | PASS; Git также вывел предупреждения о переводе LF→CRLF в ранее изменённых файлах |

Runtime-проверки изолируют клиентский код в VM. Сквозной Edge сценарий актуальности цены выполнен отдельно: сотрудник после повторного открытия каталога увидел новую цену владельца. Создание/архивация позиций и неизменность уже добавленной строки относятся к другим сценариям и этой повторной проверкой не охватывались.
