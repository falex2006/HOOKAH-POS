# FIX-04.4 — календарный день заведения

Дата: 08.10.2026. Исправление D06, локальная проверка на одноразовой PostgreSQL-базе.

## Результат

Создание и редактирование брони, её список и карточка в зале, отмена брони и пять способов освобождения стола используют одну календарную дату заведения. Часовой пояс выбирается из корректного значения точки, затем организации, затем `Asia/Yekaterinburg`. Часовой пояс Node или соединения PostgreSQL больше не меняет результат. Повреждённые старые timezone не блокируют закрытие/оплату.

Порядок состояния стола: заблокированный сохраняется; активный заказ — занят; подтверждённая бронь сегодня — забронирован; иначе свободен. Дата отменённой брони не подменяет текущий день. При переносе брони пересчитываются оба стола; создание брони не снимает занятость действующего заказа.

Проверка будущей даты POST/PATCH также переведена с часового пояса сервера на пояс заведения. PostgreSQL-путь проверяет обратное преобразование местного времени и отвергает несуществующее время при переходе DST. Системные часы не изменялись.

## Изменённая область

- `reservation-calendar.js`: общий SQL-календарь, валидация времени, пересчёт стола существующим transaction client.
- `server.js`: пять order-release путей, отмена брони, validation, зал/guards столов, счётчик и история гостя; memory-пути используют день выбранной точки.
- `db.js`: одинаковый пояс в list/create/update и конфликте времени, пересчёт старого/нового столов.
- `Dockerfile`: новый серверный модуль включён в пакет. `API.md`: контракт документирован.
- `scripts/order-close-transaction-qa.mjs`: сохранены проверки порядка операций и общего transaction client после выделения helper.
- Два новых QA-файла: `reservation-table-day-postgres-qa.cjs` и `reservation-table-day-clock-preload.cjs`.

Схема/миграции, права и финансовые правила не изменялись. Клиентские assets не менялись; синхронизация dist этому пакету не нужна.

## Проверка

Новый HTTP/PostgreSQL suite: **2203 assertions PASS**. Проверены шесть конфигураций timezone (приоритет точки, организация, стандартный пояс, отрицательное смещение UTC и два варианта повреждённых старых значений), соединения UTC/Pacific-Honolulu, моменты до и после местной полуночи.

Для каждого сочетания проверены удаление, отмена, перенос, окончательный платёж и явное закрытие заказа: HTTP-ответ, сохранённый статус в БД, повторный GET зала, исходная дата и время брони. Проверены создание/перенос/отмена брони, прошлый/будущий день, активный заказ, blocked и чужая точка. Время меняет только тестовый preload дочернего процесса; реальная БД и HTTP остаются настоящими. Ключи и пароли в отчёт не выводятся.

Чувствительность к дефекту подтверждена запуском старых server/db из локального снимка через test-only loader: после полуночи удаление заказа дало `free` вместо ожидаемого `reserved`. Текущая версия проходит тот же сценарий. Все временные базы удалены, CLEANUP PASS; рабочая QA-база и production не затронуты.

Синтаксис server/db/helper/QA, scoped `git diff --check`, `order-close-transaction-qa`, `finance-timezone-contract`, `venue-timezone-validation-runtime-qa`, `reservation-legacy-cancel-warning-contract` — PASS. Архитектор и code-health проверили итоговый diff; замечание о некорректном timezone устранено.

- `reservation-form-qa.mjs` останавливается на старом regex `portalPermissions.has` после перехода предыдущего FIX на `hasPortalPermission`; portal в этом пакете не менялся. Это ремонт QA из FIX-05.

- Memory-режим сравнивает местные строки времени; полное совпадение обработки повторяющегося/пропущенного часа DST с PostgreSQL не заявляется. Основная приёмка выполнена на PostgreSQL. Визуальных изменений нет, браузерная проверка этим запуском не заявляется.
