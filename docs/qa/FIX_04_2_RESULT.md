# FIX-04.2 — суммы оплаты на рабочем экране

Дата: 08.10.2026. Локальная синтетическая среда; production и GitHub не затрагивались.

## Изменение

Вместо двусмысленной подписи «К оплате 475 ₽» рабочий экран показывает отдельную серверную строку: **Итого 475 ₽ · Оплачено 200 ₽ · Осталось 275 ₽**. Полный итог и остаток больше не смешиваются. Для итоговой цены используется GET `/api/orders/:id/payments`; GET `/summary` сохраняет отображение скидок и доплаты до VIP-минимума. После частичного платежа и при повторном открытии окна оплаты отображение обновляется. При ошибке чтения оплаченная сумма и остаток не угадываются.

Ответ отбрасывается после смены заказа, точки или более нового чтения. Если сервер не прислал остаток, UI выводит разницу только из серверных `due` и `paid`. Никакие локальные строки заказа или каталогные цены не используются для вычисления оплаты.

Затронуты `app.js`, `dist/app.js` (ревизия app210), `scripts/staff-order-payment-summary-runtime-qa.mjs`, расширен `scripts/staff-partial-payment-pending-qa.mjs`.

## Проверка

- Runtime-контракт суммы: PASS — 475/200/275, после полной оплаты 475/475/0, повторное чтение, серверный отказ, некорректные/null суммы, вывод остатка из серверного итога и оплаченого, поздний ответ старого заказа и смена точки.
- Платёжный runtime: PASS — partial payment, повторное открытие, повтор/ошибка, double-click и существующие защиты от поздних ответов.
- `node --check app.js`, `node --check dist/app.js`, `git diff --check` — PASS; SHA256 source и dist совпадает.
- Edge, бармен: на действующем заказе видно «Итого 110 ₽ · Оплачено 0 ₽ · Осталось 110 ₽»; после перезагрузки страницы тот же заказ повторно показывает серверные суммы. Снимок: `output/qa/fix-04-2/order-summary-after-reload.png`.

Полный сценарий 475→200→275 прошёл в клиентском runtime-контракте; реальную оплату в браузере в этом этапе не отправляли. Суммы на Edge проверены на сохранённом неоплаченном синтетическом заказе. Fold отложен по решению пользователя.
