# Политика пустой настройки нового заведения

## Цель

Новое заведение должно начинать работу без чужих бизнес-данных и готовых операционных справочников. Владелец настраивает собственные цеха/подразделения, категории и каталог, технологические карты, залы, VIP-комнаты и цены.

## Начальное состояние

- Создаются только обязательные системные записи заведения, владельца и настроек, нужных для входа и работы приложения.
- Не создавать автоматически товары, ингредиенты, остатки, технологические карты, зоны/столы/VIP-комнаты или цены.
- Для склада создаются только цеха «Бар» и «Кальяны». Категории, подцеха, товары, ингредиенты и остатки владелец добавляет сам.
- Шаблон категорий применяется только отдельной командой или действием с явным выбором владельца. Регистрация и обычный deploy шаблон не запускают.
- Автоматическое создание цехов, категорий и товаров не должно зависеть от deploy или от регистрации нового заведения.
- Демо-данные должны жить только в отдельном demo/QA bootstrap. Production migration, onboarding и обычный deploy не должны добавлять демонстрационные данные.

## Что найдено в текущем проекте

- `migrations/018_inventory_departments.sql` исторически добавляла четыре стандартных подразделения существующим заведениям.
- `migrations/045_seed_inventory_departments_for_new_venues.sql` исторически добавляла те же четыре подразделения новым заведениям; миграция `101_new_venue_inventory_defaults.sql` меняет только будущие регистрации на «Бар» и «Кальяны» и не изменяет уже созданные заведения.
- `migrations/095_inventory_categories_tobacco.sql` исторически устанавливала 11 категорий; миграция 101 убирает их автоматическое создание для будущих заведений. Исторические категории текущих заведений сохраняются.
- `seed.sql` создаёт тестовые залы, обычные столы, две VIP-комнаты с депозитами/минимальными суммами, товары, ингредиенты и начальные остатки для демонстрационной площадки.
- `catalog-seed.js` содержит демонстрационные товары и технологические карты; `server.js` загружает этот каталог в memory-mode.
- Скрипт `scripts/seed-menu-catalog.js`, запускаемый командой `npm run db:seed-menu` (в частности, в текущем deploy flow), создаёт категории и товары для выбранного `VENUE_ID`.

## Миграция существующих заведений

- Не удалять справочники массово и не менять рабочее заведение до отдельного аудита данных.
- Разделить demo/seed записи и данные, созданные пользователями; проверить ссылки из чеков, заказов, остатков, техкарт, броней и финансовых операций.
- Если удаление небезопасно, архивировать или скрыть только подтверждённые неиспользуемые шаблоны; сохранять историю, внешние ключи, снимки цен и отчётность.
- Для каждой операции зафиксировать затронутые заведения, количество записей, зависимости, резервную точку и результат проверки.

## Критерии готовности изменения

- Создание нового заведения получает только цеха «Бар» и «Кальяны»; категорий, подцехов, товаров, остатков, техкарт и планировки нет.
- Экран настройки позволяет владельцу создать свои подразделения/цеха, категории, товары, техкарты, зоны, комнаты и цены.
- Обычный deploy пропускает menu catalog seed. Для его запуска требуется явный `SKIP_MENU_SEED_ONCE=false`.
- Складские категории и подцеха по умолчанию пусты.
- Существующие заведения сохраняют историю и ранее введённые пользовательские данные.
- Demo и QA сценарии по-прежнему могут получать собственный явный набор тестовых данных.
