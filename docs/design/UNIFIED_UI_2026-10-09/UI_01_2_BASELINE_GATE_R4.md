# UI-01.2 — proposed gate визуальной базы R4

2026-10-09. Владелец предложения: `system_architect`, независимый source-only contract review. Основание: [PLAN](PLAN.md) § «Проверить один раз по делу», [каталог](COMPONENT_CATALOG.md), [исключения](EXCEPTIONS.md), [условное архитектурное GO](UI_01_2_REMAINING_CONTRACT_R4.md), [R3 evidence rules](UI_01_2_ACCEPTANCE_RULES_R3.md).

**Статус: PROPOSED / NOT ADOPTED / NOT ACCEPTED.** Документ не принимает UI-01.2, не даёт runtime role PASS и не изменяет CSV. Координатор должен оформить decision, независимые signoffs и явно ввести gate в действие. До этого действуют текущие R3 acceptance rules.

## 1. Область принятия

UI-01.2 фиксирует достоверную исходную визуальную базу перед миграциями дизайна: **36 surfaces × 5 roles × 3 viewport slots × 2 requested theme slots = 1 080 baseline obligations**, плюс конечный ledger representatives empty/loading/error/long-content/keyboard и компонентов C01–C18. Исходные дефекты допустимы как просмотренные, воспроизводимые findings с владельцем. Непроверенный обязательный кадр не является дефектом продукта и не считается завершённой базой.

Все **6 480 case IDs** общей матрицы сохраняются. Exhaustive route×state/action/persistence obligations, не выполненные в UI-01.2, остаются с честными pending/rejected/defect outcomes и переходят в regression backlog **UI-09.1**. Перенос не равен PASS, N/A или equivalence. На каждом следующем продуктовом пакете проверяется изменённый и зависимый scope; полный обход системы выполняется в UI-09.1, как определяет PLAN.

Предлагаемый terminal stage status: `VISUAL_BASELINE_ACCEPTED_WITH_DOCUMENTED_DEFECTS` либо `VISUAL_BASELINE_ACCEPTED`, с точным списком findings. Это принятие материала исследования; оно не подтверждает product correctness, финансовый lifecycle, tenant isolation полного приложения или готовность release.

Новый gate заменяет только требование terminal acceptance у каждой exhaustive строки до завершения UI-01.2. Он сохраняет требования R3 к реальной роли, own route, валидному bitmap/current SHA, ограниченной equivalence, узким региональным N/A, настоящему focus и доказанной requested/actual теме.

## 2. Checklist обязательной приёмки

- [ ] Decision ID и новый gate явно записаны координатором в DECISIONS; указаны прежний gate, изменённые обязательства, причина, UI-09.1 как следующий владелец и согласующие architect/design/QA. Baseline/progress/work log согласованы с решением.
- [ ] Список всех 180 role×surface tuples сохранён, включая hashes/query и stock normalization. Все 1 080 baseline slots имеют reviewed own capture либо утверждённую ссылку с own route proof. Число файлов не подменяет число obligations.
- [ ] Actual viewport slot описывает измеренный рабочий viewport; 1366×768 и 1920×1080 измерены отдельно. Указаны actual CSS/raster dimensions, DPR, zoom known/unknown, main/document/nested scroll до/после. Bitmap показывает правильный target region после ready, а не previous route/late paint.
- [ ] Есть session bridge для каждого account/fixture и серии навигаций: UI login/session, account ID, role, tenant/organization/venue, effective permissions/policy, timestamps и действительная signature. Credentials отсутствуют. Смена account/fixture/policy инвалидирует прежний bridge.
- [ ] Для каждого baseline записаны requested/final URL, actual visible regions и settled outcome: ALLOWED, PARTIAL_READ, OWN_TODAY, POLICY_DENIED, PUBLIC_AUTH либо конкретный EXCEPTION. Auth failure, generic service error и pending не принимаются как policy denial.
- [ ] Requested dark/light context установлен до capture; actual palette и selector/context записаны отдельно. Unsupported separate palette и fixed guard invariance различаются. Supported-theme defect остаётся finding, не unsupported N/A.
- [ ] Reject decisions применены по current SHA; обязательные rejected raster/theme/focus slots пересняты и независимо просмотрены. Source-derived invariant не отменяет плохой снимок. `consistent=true` не означает визуальную приёмку.
- [ ] Конечный representative ledger составлен по §4 и заморожен для исходного source manifest: все применимые implementation/role/state classes закрыты reviewed evidence или предметным утверждённым N/A. Missing обязательный representative не переносится в UI-09.1.
- [ ] C01–C18 сопоставлены с фактически присутствующими implementations и evidence. Измерены shell/content/scroll, hit areas и typography/focus, таблицы/overflow, dialogs/layers, суммы/статусы/периоды, brand effects и auth/PIN там, где они присутствуют. Целевые размеры могут иметь documented defect; CSS declaration не считается измерением.
- [ ] Для интерактивных representatives реально выполнены действия, Tab/ShiftTab и необходимые open/close/focus-return. Dialog/select/accordion не покрываются снимком скрытого DOM. Hidden/inert controls не попадают в принятую focus sequence.
- [ ] Все выявленные findings имеют ID, source/route/role/state, current evidence SHA, воспроизведение, владельца и будущий этап. Sample data маркированы visual-only, с provenance и `persistenceValidated=false/actionsValidated=false` там, где это фактическое ограничение.
- [ ] UI-09.1 backlog сохраняет все exhaustive case IDs и исходные статусы; отдельное поле/sidecar содержит deferred owner и baseline reference. CSV не получает ложные PASS/N_A при переносе.
- [ ] Independent design review подтверждает обязательные изображения; QA подтверждает route/session/actions/readiness; architect подтверждает route/role/regions/exceptions/reuse. Координатор только после этого меняет stage status.

Эти выводы получены чтением исходников. Ни один exception в таблице не утверждён данным документом. Для fixed guard не требуется изображать несуществующий toggle: можно использовать законный requested preference context, если он доказан; когда preference неизвестна, записать `unknown` и ограничение, не выдумывать light applied. Для separate auth palette корректнее `requested slot mapped to approved fixed palette` с signoff, чем ложное «light applied».

Координатор отдельно сообщил runtime observation: у своего platform_owner account GET `/api/session/preferences` вернул 404, PATCH не выполнялся, DOM `/platform` содержит `portal velora-theme platform-page`. Этот аудит API/bitmap самостоятельно не проверял. **404 не доказывает palette exception**: он устанавливает отсутствие подтверждённого requested preference и не заменяет source+visual review. Для одобренной separate platform palette допустимы поля `requestedTheme=light` как intent матрицы, `preferenceAttempt=GET_404_NO_PATCH`, `preferenceApplied=false/unknown`, `actualPalette=FIXED_PLATFORM_DARK`, `themePolicy=UNSUPPORTED_SEPARATE_PALETTE`, `themeExceptionDecisionRef`. Это закрывает requested light baseline obligation только после architect/design signoff и current-hash actual palette review; оно не утверждает applied light. Чеклист requested context здесь выполняется документированным intent+exception, а не фиктивным preference write. При распространении на tenant business routes эта причина неприменима: фиксировать отдельно portal guard или root redirect composition по таблице выше.

## 4. Конечная матрица representatives

Единица: **source implementation/template + видимый region + role-context + state**. Theme/viewport варианты делятся там, где CSS, geometry, labels/overflow, handler или permissions дают различающийся вывод. Матрица строится из уже объявленных 36 surfaces и C01–C18; новый общий family label не объединяет разные implementations.

| Класс | Минимальные required representative states и действия | Допустимая граница reuse |
|---|---|---|
| Shell C01/C02 | Ready baseline, active navigation, доступные actions, actual content/menu scroll; keyboard links/drawer controls по присутствующему layout | Один template×role×theme×geometry; own baseline/gate всех recipient routes остаётся |
| Fresh portal policy guard | Terminal deny baseline и link Tab/ShiftTab; guard checking и service-error/Retry — отдельные representatives, если применимы | Тот же template×role×viewport; fixed theme references разрешены только по §3. Business empty/long не создаются при принятом narrow deny |
| Platform deny / root inline restriction / loaded hash guard | Каждый присутствующий template отдельно: terminal outcome, own focus; guard error/pending фиксируется отдельно от role deny | Ни один не наследует fresh portal guard только по сходству текста |
| Async collections C09/C14 | Settled successful empty, nonempty ready, pending GET, failed GET+Retry, long list/local overflow; search no-results отдельно от empty DB | Exact render/template/error handler и role read context; stock canonical/query допускают exact normalization; разные finance/payroll/history/stock layouts отдельны |
| Auth C18 | Public ready form, required validation, actual submit pending/error, длинное сообщение/username, keyboard password-toggle/remember/submit | Пять role-intent могут ссылаться на public form representative; реальные login/session outcomes ролей не наследуются. Trusted PIN/reset/setup — отдельные observed templates, если входят в проверяемый baseline context |
| Static settings/help | Ready index/topic, реальные link/accordion keyboard, expanded/full text и lower-region visibility; collection empty/read pending/error только approved regional N/A | Owner/manager settings card наборы различаются; help feedback отдельно от immutable topics; bootstrap не N/A |
| Preferences/config C04–C06/C13 | Ready read, checked/unchecked либо read-only, pending read/action, validation/save-error/rollback, long labels, actual keyboard | Exact primitive appearance возможно reuse; endpoint/payload/handler differences сохраняют отдельный behavior representative |
| Table/staff C09/C10 | Empty/no-results/loading/error/long; staff cards/list/table и 5-column overflow/scale controls по source/role; keyboard toolbar/actions | Table/card variants не объединяются; role-sensitive field visibility выделяет класс |
| Select/date/tabs C05/C07 | Реально раскрытый select/changed selection, focus, disabled/loading/error options если существуют; selected tab/date state, overflow labels | Native и custom select разные; route link и local tab не equivalent |
| Forms/dialogs/wizard C04/C11/C12 | Open/validation/pending/error/long/focus, close/Escape/backdrop и return focus как фактически реализовано; reservation steps отдельно | Native dialog, portalAction, POS и platform modal не имеют presumed общего lifecycle; не делать destructive submit ради картинки |
| POS C15 | Floor/table/order/preparation actual states, empty/no selection, loading/error если source предусматривает, long table/product/order content, panel/actions focus | Empty queue не подтверждает empty floor/order; order/payment/catalog compositions отдельны |
| KPI/status/feedback C08/C13/C16 | Known value vs unknown, actual neutral/success/warning/danger, pending/error, long amount/period/text; disclosure и retry keyboard | Ноль не unknown, disabled Telegram не empty collection; local feedback не support delivery |
| Brand/PIN C17/C18 | Source-present animation/static/reduced-motion/fallback appearance; PIN visible overlay/settings/trusted form и focus отдельно при применимости | Нет утверждения auth safety или PIN trap из hidden markup; фиксировать observed defects |

Для каждого класса выписать фактически применимые роли: owner/manager/employee/platform_owner с valid session, а не просто пять role labels. Platform_owner не получает tenant business state representatives через owner. Каждая materially distinct implementation получает ID; каждая применимая state cell — record, даже если имеет approved same-representative reference.

До signoff координатор замораживает список IDs, required states и variant classes. Тогда размер ledger конечен: сумма применимых implementation×role×state×различающихся visual variant cells. Число не назначается заранее без этой инвентаризации и не совпадает автоматически с 6 480. Baseline remains 1 080 obligations. Long/focus должны покрыть существенно разные geometry; theme-dependent appearance — обе реальные темы; identical fixed palettes можно ссылочно переиспользовать. Новая обнаруженная materially distinct implementation расширяет ledger явно до принятия, с объяснением причины.

## 6. Условия NO-GO

NO-GO при незакрытом required baseline slot, отсутствующем representative, неподтверждённом role/session gate, смешении service failure с deny, подмене requested theme, rejected обязательном bitmap, недоказанной equivalence или отсутствии независимого signoff. Непройденная exhaustive строка, честно переданная UI-09.1 и не являющаяся обязательным baseline/representative gap, сама по себе не блокирует новый research gate.

Source-only review выполнен чтением `portal-session.js`, `portal.js`, `platform.js/html/css`, `login.js/html`, `style.css`, `effective-permissions.js`, server role scopes и документации. Браузер/runtime/API tests не выполнялись; exceptions и фактическая роль не приняты. В этом пакете изменён только данный proposed gate; DECISIONS, CSV и другие документы не изменены.
