Нельзя скрыть missing required visual witness словом deferred. При source-подтверждённом отсутствии состояния меняется outcome с decision, не исчезает obligation ID.
5. Финансовый lifecycle, полный набор доменных validators, tenant/auth isolation, concurrency, запись/повторное чтение и endpoint-specific recovery — UI-09.1. В UI-01.2 реальные действия нужны лишь для достоверного открытия состояния, сообщения и фокуса. Успешная mutation и создание финансового документа не являются обязательным способом получить bitmap.

## Own-role и source bridge без размножения full tests

Одна подтверждённая browser series может покрывать несколько routes при неизменной account/session signature, tenant/venue, permissions/policy и source manifest. Не нужен повторный login или endpoint test для каждого identical visual receiver. Но у каждого requested route остаются own route JSON, final URL/hash/query, scene outcome, timestamp, bitmap/reference и привязка к этой series. Source role matrix не заменяет bridge.

Минимальный bridge содержит: account ID/role; fixture и tenant/organization/venue (null platform scope допустим и явно записан); exact effective permissions + policy и время; актуальное `/api/session` наблюдение из той же UI-сессии; реальный UI login/navigation series reference; нормализованную session fingerprint без raw token; before/after source/session freshness; source predicate и observed visible outcome. Смена account/fixture/venue/permissions, auth reset `/login`, re-login или source требует новой привязки. Credentials и token-bearing `app.js` runtime signature не копировать в evidence; сохранять безопасную нормализованную identity/permission fingerprint.

Backend fixture login 200, filename/meta.role или чужой account snapshot не sufficient. При этом полный auth isolation/RBAC suite остаётся UI-09.1: bridge лишь доказывает, **кого и что** реально снимали. Public login использует `PUBLIC_AUTH_ROLE_INTENT_ONLY`; после login.js удаления session прежний role bridge не переносится. Synthetic role/session sample не даёт own-role PASS без совпадающей actual UI series.

Непосредственно открыт current bitmap [platform_owner floor 1366 dark](evidence/UI-01.2/r2/platform_owner__floor__1366x768__dark__baseline.jpg), SHA256 **`93215c3fbcef9d4e333a21adebd01d5a09c37863dbabdfbd585a1ca721e94c14`**. Source chain: protected platform permissions `platform/diagnostics/settings` (`server.js:291`, `effective-permissions.js:10–12`) не содержат floor/orders/finance_read/finance. `app.js:40` запрещает workspace; `64` вычисляет `staffShiftReadable=false`; `82` ставит shift hidden; `98` устанавливает terminal inline restriction; `99` не вызывает refreshShift без shift rights; `219` имеет early return. `portal.js:7` исключает platform_owner из tenant allowlist и redirect `/` для тех admin hashes, которым portal-session gate разрешил settings/diagnostics. В `style.css:2894` shift-control получает `display:inline-flex`, а соответствующего override для hidden этого header control в просмотренном блоке нет. Это source-обоснованный **кандидат причины** ghost pending control; CSS declaration может переопределять UA hidden display. Computed style/hidden для самого shift элемента во время снимка здесь не измерены, окончательная root cause не утверждается. Видимый pending подтверждён bitmap, permission-inapplicable source state подтверждён указанными predicates.
