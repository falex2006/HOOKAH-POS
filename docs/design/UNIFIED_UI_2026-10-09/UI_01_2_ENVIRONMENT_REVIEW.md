## Изоляция, auth и владение ресурсами

- Setup создаёт отдельный именованный Docker-контейнер и свежую БД, отказывается перезаписывать существующий private runtime или использовать уже существующий контейнер этого имени. PostgreSQL публикуется только на `127.0.0.1:31954`. Production connection string не импортируется.
- Launcher сверяет имя контейнера, БД и порты, передаёт backend ограниченный набор переменных среды; `HOST=127.0.0.1`, порт 31953, настоящая авторизация включена, demo и first-run setup выключены. Секреты стенда генерируются локально. Проверка 215 файлов подтверждила ноль расхождений mirror и root с исходным SHA256 manifest.
- Fixtures обращаются к фиксированному loopback proxy 31952, используют синтетические учётные записи и данные. В коде нет создания заказов, платежей, смен, payroll или проводок. Tenant auth остаётся продуктовым контрактом; изоляция API между tenant этим ревью не проверялась.
- Proxy меняет только выбранные успешные GET data responses (`200..299`), после настоящего upstream ответа. Следовательно, ветка synthetic loading/error/empty не преобразует upstream 401/403. Auth/session/logout/health/brand/venue защищены в proxy; controller дополнительно запрещает auth/preference targets. Сохранённый authentication evidence содержит девять login 200 с ожидаемыми ролями и unauthenticated session 401; runtime-тест 403 отсутствует.
- Владение ограничено конкретным UI012-контейнером, его отдельным volume и процессами стенда. PID-файлы и инструкция требуют сверять command line с точным каталогом перед остановкой. Teardown не выполнен; PID сам по себе не является достаточным доказательством владения из-за возможного повторного использования номера. Режимы proxy глобальны для стенда, поэтому параллельные state captures требуют координации.

## Секреты и найденный риск

**P1 — первоначально временный каталог не был исключён из Git. Исправлено координатором.** Первый `git check-ignore` не вернул private runtime/credentials, `git status` показывал untracked `tmp/ui012-baseline/`. Первопричина — отсутствующий scoped ignore; риск — случайный stage временных паролей вместе со стендом. Минимальное исправление: локальная запись `/tmp/ui012-baseline/` в `.git/info/exclude`. Повторный `git check-ignore` подтвердил оба приватных файла; `git status --short -- tmp/ui012-baseline` пуст. Владелец исправления — координатор. Локальное exclude не переносится в другие checkout, поэтому там требуется своя защита перед staging.

В 90 текстовых файлах отчёта/evidence не найдено точных значений сгенерированных runtime-паролей и ключей; JSON evidence не содержит имен полей password/token/authorization/sessionSecret/dbPassword/appKey/database_url. Значения секретов не выводились. Setup исключает `.env`, private runtime и существующие БД из копирования; auth evidence содержит только статусы, роли и синтетические tenant IDs. Это подтверждает отсутствие обнаруженной утечки в проверенном текстовом evidence, но не является полным поиском неизвестных production-секретов или анализом каждого пикселя JPG.

## Ограничения инструмента перед повторным использованием

Это локальная одноразовая instrumentation, а не production harness. Fixtures не идемпотентны после завершения: повторный запуск может создать дубликаты сотрудников/контента; инструкция запрещает такой replay. Перед restart проверять принадлежность портов, процессов и исходного snapshot.

**P2 — устойчивость finalize при изменённом наборе evidence.** Helper предполагает правильную CSV schema, корректный JPEG и однозначную пару capture/case; не валидирует обязательные headers и не очищает все старые evidence/dimension fields у вновь blocked rows. Текущий набор прошёл независимые проверки, поэтому это не дефект текущего результата. Сценарий риска: удалить ранее mapped capture и повторить finalize — его прежняя ссылка может остаться на blocked row. Первопричина — частичный reset строки; владелец — координатор/instrumentation. Минимальное исправление перед таким повторным прогоном — очистить evidence/measurement/dimension/defect fields, валидировать headers и уникальность mapping до записи. Regex переноса классов также зависит от текущего формата Markdown-таблицы; при изменении формата повторять структурную сверку.

**Итог:** новых блокирующих дефектов текущей изоляции или сохранённой обработки evidence после исправления scoped ignore не обнаружено. Пригодность environment не доказывает браузерные сценарии всех ролей. После сообщённого восстановления Edge можно продолжать UI-проверку по остатку baseline и обновлять evidence по фактическим результатам; переход к следующему UI-подэтапу этим отчётом не разрешается.
