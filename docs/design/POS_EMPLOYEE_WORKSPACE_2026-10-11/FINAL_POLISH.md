# Финальная визуальная доводка POS

Дата: 11.10.2026. Результат локального visual review: PASS. Область: карточки столов, панель заказа, кнопки, отступы и обе существующие темы. Работа выполнена в изолированном worktree `pos-employee-workspace`, база `f7e7af1381cb081662b85c53447fd73cb935c6e6`. Исходный dirty checkout не изменялся. Окончательная эстетическая оценка остаётся за владельцем.

## Изменения

- Сетка «Вместить» использует доступную ширину: маленький зал больше не превращается в одну колонку широких карточек на большом мониторе. Автоматическая высота ограничена 132–144 px; вместимость, время, сумма и приготовление занимают отдельные строки. Длинное название сокращается визуально с сохранением полного accessible name. PS5/ТВ и бейдж не пересекаются.
- Выбранный стол получает тематическую рамку; клавиатурный фокус отличается пунктирной внешней рамкой. Закрытый стол сохраняет читаемый текст. Цвета взяты из существующих семантических токенов.
- Панель заказа начинается рядом с управлением размером столов. Служебные блоки компактнее, подсказка показывает прежние подтверждённые числа новых/переданных позиций. Вкладки выровнены по центру, обычные суммы используют одинаковую минимальную ширину колонки. На невысоком экране уменьшены отступы; размеры целей и текст сохранены.
- При ширине до 1320 px переключатель и три счётчика занимают отдельные строки, чтобы длинная подпись не пересекалась с числом.
- Предупреждение прокрутки учитывает фактически отрисованную высоту сетки после появления суммы, бейджа и оборудования. ResizeObserver отслеживает изменение содержимого; расчёт компенсирует настоящую высоту предупреждения и row-gap.

Source/dist пары: `app.js`, `pos-workspace.css`, `index.html`; `pos-workspace.js` восстановлен в точное исходное состояние этой итерации и также совпадает с dist. CSS rev3, app rev2026101108. Канонический appRevision согласован в `scripts/sync-published-assets.mjs`; общий sync не запускался. Ручной размер 70–130% и сохранение по сотруднику/заведению остаются прежними. API, сервер, RBAC, направления отправки и финансовые расчёты не менялись.

## Независимая проверка и границы

Design lead: финальный visual review PASS на 1366×768, 1366×600, 1181×768 и 320×740 в обеих темах; пересчитаны effective contrast и геометрия. System architect: focused boundary/manual70 audit PASS, warning стабилен; header/sidebar/routes и права сохранены. Code health: итоговый PASS, новых блокеров нет. Независимо пройдены 18 целевых контрактов, local-static-boundary, syntax, diff-check, 33 semantic refs и четыре зеркала. Дополнительно проверены 10 actual Fit cases (1366×768/820/840/860/900 × обе темы), динамическое удаление/возврат оборудования без resize с корректным warning, ручные 70→130→70, selection/keyboard focus и first-quantity/CTA/More на 1366×600. JS/Console errors и API writes = 0; все три замечания P2 этой итерации устранены.

Координатор: syntax, diff-check и четыре source/dist пары PASS. Целевые контракты PASS: staff-table-density, semantic-token, local-design, header-shell, component-primitives, staff-shell-parity, floor-order-total-label, order-payment-summary-runtime, partial-payment-pending. До изменения зафиксирован immutable baseline в ignored `tmp/full-local-qa/pos-final-polish-baseline/`.

У baseline уже есть сбои `visual-page-rules-contract` (mockDocument без querySelector) и `fold-responsive-contract` (устаревшее ожидание compact-map). Они не исправлялись этой задачей; полный общий suite не объявляется зелёным. Chrome headless matrix и один реальный Edge preview не подтверждают физический POS/Fold, все режимы Windows scaling или полную WCAG-сертификацию. Нового mutating business replay не требовалось для этой визуальной правки; предыдущие функциональные доказательства описаны в [ACCEPTANCE.md](ACCEPTANCE.md).

Push, merge, deployment и production операции не выполнялись. Собственный локальный preview оставлен работающим для просмотра.
