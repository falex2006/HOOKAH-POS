# Цвета состояний и оснащение столов

Локальная доводка по согласованию пользователя, 13.10.2026. Изолированный worktree `pos-employee-workspace`, без публикации и изменения БД.

- Нейтральные: занят, в процессе, обычное приготовление и общий счётчик приготовления.
- Янтарные: очередь, ожидание оплаты; прежняя подпись брони сохранена. Наличие открытого счёта само по себе не создаёт тревожного акцента.
- Зелёные: свободный стол и готовность с текстовыми подписями.
- Красные: отмена/ошибка/опасные действия; фирменная заливка главного действия и тонкий выбранный контур сохранены.
- В смешанном приготовлении ожидающие позиции показываются раньше обычного «в работе», чтобы ожидание не терялось.
- ТВ и геймпад: одинаковые SVG 20px, нейтральный цвет, без рамок и плашек, отдельная нижняя строка справа. У каждого есть доступное имя и подсказка; значки появляются только по существующим признакам оснащения.

Проверка значков использует явно обозначенные GET overrides в изолированном браузере: в постоянной синтетической fixture оснащение не задано. Это не изменение конфигурации столов и не запись вымышленных удобств в БД.

Снимки примеров: [тёмная тема](evidence/floor-1366-dark.png), [светлая тема](evidence/floor-1366-light.png), [телефон](evidence/floor-320-light.png). Координатор просмотрел реальные изображения. [Данные проверки](evidence/qa.json).

## Проверка
Фокусный браузерный прогон: desktop1366 и mobile320, обе темы, плотности70/100/130, стол с заказом+ожиданием+обоими значками, варианты оснащения оба/один/нет. Проверены контраст текста>=4.5 и значков>=3, отсутствие переполнения, рамок/плашек, доступные названия и расположение внутри карточки справа внизу. JS errors=0, API writes=0. Семантические токены, primitives, density, local-design, navigation, workspace и dispatch26 — PASS; source/dist4 пары, syntax/diffcheck — PASS.

Исходный order-preparation-ui-qa имеет старый mock без classList.toggle; это не регрессия текущих двух изменений разметки app.js. Полная кассовая E2E и WCAG здесь не заявляются. Baseline tmp/colors-baseline, роли design_lead и code_health_engineer.
