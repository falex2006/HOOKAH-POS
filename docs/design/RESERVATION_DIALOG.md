# Бронирования: форма в пошаговом окне

> Действующая предметная спецификация, подчинённая общим [VISUAL_PAGE_RULES.md](../../VISUAL_PAGE_RULES.md), [DESIGN_TOKENS.md](../../DESIGN_TOKENS.md) и каталогу компонентов UI-01.1. Зависимости `/api/clients` и `/api/floor` ниже подтверждены чтением локального дерева и `origin/main` на этапе UI-01.1. Сценарий роли только с `reservations` остаётся непринятым; отдельных ограниченных selector API в этих исходниках нет. Доказательства и границы доступа: [ROUTE_ROLE_MATRIX.md](UNIFIED_UI_2026-10-09/ROUTE_ROLE_MATRIX.md).

## Задача

На странице остаются текущие брони, поиск/дата и одна заметная кнопка «Новая бронь». Форма появляется в диалоге:1.Гость и телефон;2.Дата/время/место/число гостей;3.Требуемый депозит/комментарий/проверка. В обычной настольной высоте сотрудник не прокручивает страницу ради формы. На коротком экране допустима прокрутка внутри окна.

## Контракт

Существующий renderReservations и ID формы сохраняются. GET /api/reservations отдаёт список; POST создаёт, PATCH /api/reservations/:id редактирует. Используется прежний api() wrapper с контекстом текущей точки. Поля:guestName,clientId,phone,date,time,tableId,guests,deposit,notes,createdByName,createdByRole. deposit — требуемая сумма, не факт оплаты. Квитанции/возвраты/начало визита остаются в списке.

GET /api/floor даёт места, вместимость и минимум; GET /api/clients — подсказки гостей. Права сервера не расширяются. Известная исходная особенность: роль только с reservations без floor/orders не получает селекторы; это отдельный серверный вопрос, не изменение данного UI.

## Поведение

Назад/далее сохраняют ввод. Финальная валидация открывает нужный шаг до reportValidity. Во время сохранения блокируются повторный submit, шаги и закрытие. Ошибка сохраняет ввод. Успех закрывает окно, показывает уведомление и запись на её дату. Редактирование открывает те же поля без сброса. Диалог возвращает фокус, закрывается Escape/кнопкой; открытый custom select обрабатывает Escape первым. Сохраняются tableId/reservationId/action=seat deep links.

## Проверка

Локальный полный create→list→reload→edit путь, ошибки/обязательные поля, capacity/deposit, Escape, фокус и desktop/narrow layout. Production только чтение/открытие окна, без создания тестовых броней.
