Продуктовая основа f7e7af13; план 8ef9f147. В этом этапе изменена только документация. Сервер не затрагивался, приложения/БД/данные/права/маршруты не менялись, бизнес-тесты не повторялись.

## Принятые решения темы

1. Графитовая тёмная основа, умеренный фирменный акцент, читаемые статусы с подписью. Короткие эффекты и reduced-motion. Никаких decorative sums, shine/sweep или новых «умных» KPI.
2. Существующие semantic tokens/Manrope/размеры — основа. В одной группе кнопки одной высоты. Ошибка, предупреждение, недоступность и неизвестное значение оформляются различимо.
3. Verified роль, tenant и включённый маршрут/подкомпонент определяют область темы. Путь сам по себе недостаточен; staff ветки shared URLs исключены. Body-mounted окно получает собственное происхождение/marker.
4. Зал/столы, `/`, персонал, права и профили сотрудников не оформляются. Аналитика сотрудников/выбор ответственного в финансовой или задачной форме — данные разрешённого модуля, не страница персонала.
5. Company/settings содержат зальные узлы: включать только согласованные панели. `/platform` и developer context — отдельный контур, сюда не входят. Управленческая карточка смены включена, рабочая кнопка смены исключена.
6. Предложенные картинки — ориентир характера, не спецификация функций. Данные образца помечаются примерными; подпись «Нужно пополнить» соответствует позиции ниже минимума.
7. Существующая light preference сохраняется. Нельзя распространять тёмные новые tokens на body целиком или ухудшать существующий доступный режим; полноценная новая light-концепция не принимается MT-01.

## Представительный образец MT 02

Одна desktop ширина **1440×900**, без mobile/Fold/матрицы дополнительных разрешений. Масштаб текста и длинные данные — контроль устойчивости компонента, не отдельная адаптация продукта. Образец локальный, не подключён к рабочему серверу/API.

| Группа | Образцы | Состояния |
| --- | --- | --- |
| Главная | D01–D04 | Дневные/сменные подписи, нет смены, zero, unknown, большая сумма, warning |
| Таблица склада | IM-01 и C18/19 | Ready, empty, no matches, loading, error, длинное имя/единица/количество |
| Inline длинная форма | IM-03 либо F09 | Required/optional/readonly/disabled, ошибка поля/API, pending, сохранённый ввод |
| Shared dialog | C07–C11, D13 | Long scroll, focus/return, close/cancel/draft, step back/next/review |
| Critical и legacy | C12/C13, F12 | Подтверждение с суммой и последствием, pending блокирует action, неизвестный результат, legacy отмена |
| Feedback/центр | C14–C16 | Success/info/warning/error, длинный текст, sticky error, unread=0, tray empty/loading/error |
| Controls | C01–C06/C23/24 | Hover/focus/pressed/disabled/busy, select groups, native date отличие, normal/reduced-motion |
| Финансовая недоступность | F01/F16/F17 | Неизвестное/недоступное != ноль; preview != официальный результат; понятный период/единицы |

Не рисовать обычный success после неопределённого API результата. Интеракции в образце симулируются и явно не выполняют оплату/приход/возврат. Предложенные новые lifecycle controls (например, close у sticky toast) обозначаются как proposal до решения MT-03.

## Проверки внедрения без повторных общих аудитов

| Проверка | Связанные записи | Когда выполнять |
| --- | --- | --- |
| A01 Геометрия, одинаковая высота/gap, long text, controls keyboard | C01–C06/C18/19 | Семейство в MT-02, затем изменённые потребители; не весь продукт после каждого цвета |

| A04 Toast/inline error/notifications | C14–C16 | Не исчезающая важная ошибка, длинный текст, порядок событий, retry; API не вызывается в MT-02 |
| A05 Zero/unknown/error/source/period | C17/F01/F02/F16/F17/D01/IM KPI | Образцы и каждый изменённый KPI renderer; helper `money(value||0)` не подменяет caller readiness |
| A06 Theme isolation | Route contract/C20/21 | admin → staff/permissions/venue-layout → назад; shared route с иной ролью; marker отсутствует в исключённой ветке |
| A07 Session/async context | C08/C12/C16/21 | Denied hash, logout/expiry/venue switch, stale completion, bfcache/back; без расширения прав |
| A08 Доменные write/readback | IM/F/D caller | Только затронутые handlers на изолированной базе. Если handler/payload не менялся, существующий результат переиспользуется с соответствующей версией |
| A09 Source/dist, syntax, diff | Реально изменённый код | По пакету MT-03/04; не запускать sync/build ради MT-01 |

Контрольный снимок исключённого экрана служит доказательством отсутствия изменений, не разрешением заниматься его дизайном. Существующие scripts — кандидаты; до использования читать актуальные assertions, не чинить продукт ради устаревших строк теста.

## Обнаруженные точки внимания и владельцы

| Наблюдение из кода | Решение и владелец |
| --- | --- |
| Shared/legacy/native и inline формы имеют разные lifecycle | Frontend + QA используют отдельные представители; не объявляют общий контракт автоматически внедрённым |
| Dialog/feedback/tray создаются в body, theme marker не наследуется из content | Архитектор фиксирует provenance/resolver; frontend реализует scoped marker; QA A06/A07 |
| Denied hashchange может остановить поздние listeners | Архитектор/Frontend: theme teardown независим от позднего renderer; QA denied transition |
| Некоторые formatters приводят missing к 0, KPI имеют самостоятельные состояния чтения | Владелец домена подтверждает caller readiness; визуальный слой не «исправляет» сумму глобальным formatter |
| Категории финансов: gate страницы строже подписи ссылки; payroll имеет собственные gates | Сохранять реальный verified/server gate. Это не новый запрос расширить доступ |
| Нет подтверждения общего toast close/queue, lifecycle каталогов индивидуален | Не обещать готовую функцию. Показать визуальный вариант; если внедрение требует поведения — минимальная отдельная правка с проверкой |
| Нативные picker/validation/confirm UI управляет браузер | Приёмка явно отделяет их; стилизованный confirm не появится от CSS без отдельного lifecycle решения |

Это ограничения внедрения новой темы, а не список незавершённых прежних задач. Обнаруженный будущим exercise бизнес-дефект оформляется конкретно, не скрывается стилями и не превращается автоматически в широкий аудит.

## Контроль завершения MT 01

- Реальные маршруты и guards прочитаны, включённые/исключённые области заданы.
- 92 записи имеют source anchors и состояния; семейства и потребители связаны через C/IM/F/D.
- Существующие имена QA сверены с файлами scripts; функциональный PASS не заявляется.
- Представительный набор MT-02 и будущие A01–A10 определены; новые исходные тесты не добавлены и не запускались.
- Профильные исследования архитектора, design lead и финансового каталога сведены координатором. Независимая финальная проверка нашла неподтверждённый пример finance CSV; заменён на реальный audit export. Блокирующих замечаний к каталогу после исправления не осталось.
- Следующий этап — MT-02 на GPT-6.1 Sol / Medium / Standard, без автоматического переключения модели или массового переноса CSS.
