# MT-01 — финансы, зарплата, отчёты и лояльность

Статус: каталог по исходникам, без запуска приложения, API и QA. Наличие сценария в коде и имени проверки не означает успешную проверку. Основа: `portal.js`, `portal-session.js`, `payroll-scheme-ui.js`, шаблоны `finance*.html`, `SITE_TREE.md`. Бизнес-логика, суммы, права и маршруты не изменяются.

## API, сохранение и инварианты отображения

- Сводка читает `/api/finance/summary?date=…`, состояние смены и `/api/analytics?days=all`. Дата сводки, выбранный период графика, общие итоги аналитики и средний чек текущей смены имеют разные основания. Не объединять их подписью «сегодня».
- Отчёт читает `/api/finance/report?date=…&type=x|waiter`: продажи — дата закрытия чека; получение/возврат денег — дата операции. `money`, `localDateKey`, `formatRuDate`, `venueTimezone` сохраняются; unavailable/null, ноль и отсутствие деятельности — разные состояния.
- `/api/expenses` — POST и перечитывание журнала/сводки; категория должна быть активной `expense`. Закупка имеет ссылку на проведённую поставку и отдельную оплату; форма не заменяет эту связь. Исторические категории и payroll-status нельзя потерять в строках.
- `/api/finance/purchase-payables/:id/payments` — POST с `amount/paymentDate/paymentMethod/documentUrl/idempotencyKey`; ключ хранится у формы. Есть проверка остатка, файла и повторного запроса. При ошибке форма остаётся; не добавлять новый ключ на косметический rerender.
- `/api/finance/categories` POST/PATCH и последующее чтение: архив сохраняет исторические операции; восстановление отдельное. Pending охватывает редактор, список и закрытие; подтверждение через `portalConfirm`. Ошибка обновления списка после успешной записи имеет отдельное сообщение.
- `/api/payroll/entries` POST; `/:id` PATCH по жизненному циклу; UI перечитывает реестр/расходы. Дата выплаты обязательна для оплаты, основание для отмены; начисление не равно выплате. Локальный disable/Set в UI не является доказательством серверной идемпотентности.
- `/api/payroll/schemes`, `/versions`, `/:version/activate`, preview/compare, source-readiness и attendance approvals обслуживает `payroll-scheme-ui.js`. Версия/валюта/период/источник и текст «неофициально» остаются; grids сохраняют unknown JSON, пустое optional отличается от нуля. Attendance approval отправляет watermark/reason/idempotencyKey. Не включать официальный расчёт косметикой.
- Сверка `/api/loyalty/reconciliation?from=…&to=…`: движения за период в часовом поясе заведения; текущие балансы и обязательства — сейчас. Bonus points, деньги гостя и предоплата брони — разные единицы/источники. Preview без журналов не обозначать полноценной сверкой.
- `/api/discount-groups` POST/PATCH и reload; `/api/loyalty/settings` PATCH содержит `expectedVenueId/expectedVersion`, курс фиксирован 1 ₽; `/api/loyalty/promotions` POST/PATCH содержит venue/version, периоды конвертируются из IANA timezone, условия версий неизменяемы для сохранённой истории.
- Во всех формах «сохранено» относится к подтверждённому API ответу. Disabled и локальный pending сохраняются; backend idempotence/tenant validation здесь не исследованы и не подтверждены. Focus trap/return, Escape, outside-click и предупреждение несохранённого ввода проверять по общему контракту окон, не объявлять реализованными для всех форм по одному dialog.

## Открытые границы для MT-02/MT-04

- Все визуальные состояния таблицы имеют статус «не проверено в браузере»; имеющиеся QA перечислены для выбора затронутого пакета, ни один здесь не запускался. Выплаты, расходы, архив и ledger проверять только на изолированной базе.
- Тема должна сохранить исключённые сотруднические ветки `/finance` и `/finance/report`, общий header/navigation и контракт `#payroll`; архитектурное подтверждение границы темы требуется до CSS переноса.
- У программ/акций есть собственные формы и pending механизмы; единое управление pending, закрытие/несохранённые изменения и повторный submit не доказаны для каждого сценария. Если будущая проверка найдёт функциональный пробел, регистрировать отдельно от MT-косметики.
- В MT-02 представить образцы F09/F15/F21 (длинная форма), F12 (окно/опасное подтверждение), F01/F11/F17 (loading/empty/API error), F07 (disabled/pending), F16 (warning/unavailable) с явно примерными данными. Не считать браузерный образец фактической финансовой сверкой.
