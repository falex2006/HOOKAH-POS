# MT-01 — склад, меню и техкарты

Статус: каталог по исходному коду; браузерные состояния и функции в этой задаче не проверялись. Источники: `SITE_TREE.md`, `portal.js` (`renderInventory`, строки 3160–4542), `inventory.html`, существующие файлы `scripts/`. Наличие скрипта означает кандидата для повторного использования, а не успешный запуск на текущей версии.

Все семь представлений принадлежат `/inventory`; без `view` открываются остатки. `setInventoryView` и `inventorySections` сохраняют query/history и показывают соответствующие панели. `/admin#menu` не найден как действующий раздел: `focusedAdminDashboardHashes` не содержит `#menu`; каталог продаж и техкарты находятся на `?view=products` и `?view=recipes`. Новый маршрут из этого каталога не следует.

Обозначения прав: **R** — вход/чтение `inventory_read`; **W** — управление `inventory`; **C** — отдельное `inventory_categories` для жизненного цикла категории; **F** — `finance`. Это обнаруженные UI gates, окончательное разрешение операции остаётся на сервере. Не превращать роли owner/admin/manager в одинаковые права.

## Повторное использование и границы доказательств

- Существующие классы `.ui-button`, `.ui-input`, `.ui-field`, `.ui-badge`, `.ui-table-region`, `.ui-modal-card/body/footer` уже монтируются в этих представлениях; `mountInventoryCatalogPresentation` охватывает каталог/рецепты/справочники. Это потребители общего контракта MT-01, не разрешение перекрасить все `.panel` или все страницы.
- Подтверждения перечисленных опасных операций часто реализованы `window.confirm`. Образец MT-02 может показать предлагаемую визуальную оболочку с примерными данными; это ещё не замена рабочего контракта подтверждения в приложении.
- Скрипты с Postgres/browser/E2E требуют изолированной QA-базы и могут создавать записи. В MT-01 они только сопоставлены с компонентами; сервер и проверки не запускались. Mobile/Fold-скрипты не включены в матрицу desktop приёмки.
- Для покрытия исходных сценариев предпочтительны `acceptance-44-inventory-crossflow-postgres-browser-qa.mjs` и профильные проверки из таблицы; успешность исторического запуска не переносится на текущий diff.
