# UI-09.2: ограниченный кандидат интерфейса

Локальный пакет интерфейса UI-01.1–UI-09.1, реконструированный поверх сохранённого origin/main `2e6f557934fe29a9a227dda73277f6c3f99af939`. Это подготовка кандидата, не разрешение публикации. Точный commit, дерево, архив и SHA256 указаны во внешнем release manifest.

## Состав и границы

Перенесены UI012→UI091 изменения восьми исходных файлов, общий `ui-dialog.js`, принятая декларативная карта системы, дизайн-контракты и focused проверки. Отдельно сохранены принятые зависимости каталога и карточки заказа: Escape, возврат фокуса, pending controls, «Вернуться к заказу», статусы и подсказка следующего действия. Эти фрагменты существовали в immutable UI012 до начала UI-этапов; их происхождение и hashes записаны отдельно. Полное старое рабочее дерево не включено.

DB/schema/migrations/packages, tenant/permissions/routes и бизнес-обработчики сохранены из base. В server добавлена только статическая доступность общего dialog-модуля. Сохранены upstream `table-minimum-schedule.js` и проверка пары времён. Docker COPY, sync source/dist и ключи кэша `2026101101` включены в пакет. Данные пользователей и временные QA файлы исключены.

## Обязательства перед UI-09.3

- Явный отдельный запуск публикации; clean integration/PR/CI и сверка SHA. Если merge меняет SHA, архив и manifest создаются заново.
- Свежая критическая desktop проверка именно этого кандидата: обе темы, роли, login/logout, keyboard/focus, заказ/приготовление, редакторы и финансовые сценарии в изолированной среде. Старые browser снимки UI091 относятся к исходному WIP и не подтверждают перенесённый кандидат.
- Определить обязательные непроверенные role×theme×state клетки. Полный Cartesian, Edge, WCAG и OS reduced-motion не приняты. Fold — отдельный UI-10.1.
- Разобрать применимость старых security findings: чужой PIN, lock non-OK PATCH, escaping audit CSV. UI-09.2 их не исправляет и не снимает.
- Проверить текущие VPS SHA/image IDs, migration ledger и совместимость старта; сделать backup с integrity и restore rehearsal. Локальная сборка не доказывает состояние VPS.

## Backup и откат

Следовать существующим `deploy-vps.sh`, `backup-postgres.sh`, `verify-backup.sh` и DEVELOPMENT_WORKFLOW. Перед выпуском сохранить предыдущие commit/archive/image IDs, compose и конфигурацию без вывода секретов; защищённый backup PostgreSQL в `/var/backups/territory-crm/<project>`. Проверить архив, checksum и восстановление в отдельной БД/volume. Проверить HTTPS, AUTH_REQUIRED и COOKIE_SECURE; сохранить deployment lock и release fingerprint. Не включать автоматический seed при существующих данных.

В этом UI-пакете новых миграций относительно base нет. На VPS ledger может отставать: существующая схема и порядок запуска/миграции требуют preflight; при несовместимости подготовить maintenance-порядок до запуска приложения.

Откат: остановить затронутые write flows при необходимости, вернуть сохранённый совместимый app image/commit и конфигурацию, проверить health/session/roles. БД не откатывать удалением миграций; новые транзакции сохранять. Восстановление production БД допустимо только по отдельному согласованному плану восстановления данных. Backup/restore/deploy сейчас не выполнялись.
