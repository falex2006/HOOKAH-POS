# Расписание минимального чека стола

Настройка хранится у стола и редактируется в разделе владельца «Залы, этажи и столы». Она состоит из суммы и необязательной пары локальных времён. Пустая пара оставляет старое поведение: сумма применяется всегда. Пара `18:00`–`09:00` задаёт ночное окно `[18:00, 09:00)` по часовому поясу конкретного заведения.

| Шаг | Контракт |
| --- | --- |
| Настройка | Создание/редактирование стола в UI отправляет `minimumOrderTotal`, `minimumOrderStartTime`, `minimumOrderEndTime` в `POST/PATCH /api/floor/tables`. |
| Права и tenant | Сервер проверяет `settings`, ожидаемый venue и принадлежность стола/зоны активному заведению. |
| Сохранение | Миграция 100 добавляет nullable `TIME` поля; пара времён ограничена проверкой в API и БД. |
| Повторное чтение | `GET /api/floor` возвращает сохранённые время и сумму; панель настроек показывает их после обновления. |
| Создание заказа | `POST /api/orders` применяет политику на сервере; клиентская сумма не авторитетна. PostgreSQL вычисляет её под блокировкой строки стола, а memory-режим использует тот же helper. |
| Бронирование | `POST/PATCH /api/reservations` проверяет минимум по времени начала брони в часовом поясе заведения. Дневная бронь не требует ночной минимум, даже если её создали заранее. |
| Снимок | Активная сумма записывается в `orders.vip_minimum`; правка расписания не меняет уже созданный заказ. |
| QA | `scripts/table-minimum-schedule-qa.mjs` покрывает границы, ночной переход, timezone площадки, невалидные пары и совместимость статичного минимума. |

Пустая пара является совместимым режимом для старых столов. Время создания нового стола по умолчанию выставлено в `18:00`–`09:00`; уже существующие столы не меняются автоматически.
